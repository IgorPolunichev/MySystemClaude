# ADR 0009. Продуктивные часы из интервала работы минус перерывы

- Статус: принято (уточнение заказчика после этапа 3; заменяет п. 4 ADR 0008 в части ввода часов)
- Дата: 2026-10-23

## Контекст

На этапе 3 в табель вводилось число часов. Заказчик уточнил: часы должны рассчитываться из промежутка времени. Пример: инженер работал с 10:00 до 13:00, обед с 11:00 до 12:00 — продуктивных часов 2.

## Решение

1. Ячейка табеля «инженер × день» хранит **интервал работы** (`start_time`, `end_time`) и **перерывы** (`time_entry_break`, любое количество). Продуктивное время **рассчитывает сервер** (`TimeEntry.workMinutes()`): длительность интервала минус перерывы. Клиент повторяет расчёт только для подсказки (`workTime.ts`, те же тесты).
2. **Источник правды — минуты** (`work_minutes`). Часы = минуты / 60 с округлением до сотых только для показа; итоги акта и дня считаются из суммы минут, поэтому ошибка округления не накапливается.
3. **Ночная смена:** окончание не позже начала — работа до следующего дня, часы относятся к дате начала; окончание = начало — ровно 24 ч. Перерывы могут переходить через полночь.
4. **Проверки:** указаны и начало, и окончание; перерывы внутри интервала, не пересекаются и не занимают всё время; сумма продуктивного времени инженера за день по всем неаннулированным актам — не больше 24 ч, больше 12 ч — предупреждение.
5. **Время в пути** остаётся отдельным числом часов (шаг 0,25 ч). Запись может содержать только время в пути — без интервала.
6. **Миграция** `V3__time_intervals.sql`: записи, введённые числом часов, получили интервал 09:00 + столько же часов без перерывов — итоги не изменились.
7. API: `PUT /acts/{id}/time/{engineerId}/{date}` принимает `startTime`, `endTime`, `breaks[]`, `travelHours`, `comment` (поле `hours` во входных данных убрано); ответ содержит `startTime`, `endTime`, `breaks`, `workMinutes`, `hours`.

## Последствия

- Excel (этап 5) выводит на листе «Табель» интервал, перерывы и продуктивные часы по каждому дню.
- `analytics-service` (этап 7) суммирует `workMinutes` из событий `TimeEntryChanged` (в событии есть `workMinutes`, `startTime`, `endTime`).
- `SPEC.md` обновлён: разделы 5 (`time_entry`, `time_entry_break`), 6.4, 7, 9, 14.
