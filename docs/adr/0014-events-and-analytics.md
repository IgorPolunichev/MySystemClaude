# ADR 0014. События через RabbitMQ и аналитика продуктивных часов (этап 7)

- Статус: принято
- Дата: 2026-10-24

## Решения

1. **Spring AMQP напрямую** (`spring-boot-starter-amqp`), без Spring Cloud Stream: один брокер, простая топология, меньше зависимостей, которые нужно согласовывать со Spring Boot 4.
2. **Отправка outbox** (`act-service`, `OutboxRelay`): раз в секунду пачками по 100 в порядке создания, строки блокируются `FOR UPDATE SKIP LOCKED`, отметка `published_at` ставится в той же транзакции. Обменник `acts.events` (topic), ключ маршрутизации — тип события. Доставка «хотя бы один раз». Включается `OUTBOX_PUBLISH_ENABLED=true` (в Docker Compose), в тестах выключена.
3. **События самодостаточны:** каждое событие акта несёт статус, номер, заказчика, технику и площадку (`actPayload`), `TimeEntryChanged` — инженера, дату и `workMinutes` (0 — запись удалена). Потребителю не нужно обращаться к `act-service`.
4. **`analytics-service`**: очередь `analytics.events` (привязка `#`), read model `fact_act` и `fact_time` (минуты инженера по дню и акту). Каждое событие применяется один раз (`processed_event`) в одной транзакции с изменением. Конверт разбирается собственным `JsonReader` (не зависит от версии Jackson). Ошибочное сообщение пишется в журнал и пропускается; расхождения устраняет полная пересборка `POST /api/v1/analytics/rebuild` (администратор) по выгрузке `GET /api/v1/acts/analytics-facts`.
5. **Факт** — минуты по актам в статусах `OPEN` и `CLOSED` (черновики и аннулированные не учитываются), агрегаты считает PostgreSQL. **Норма** на период — сумма месячных норм, неполный месяц — пропорционально рабочим дням (`NormCalculator`, `WorkCalendar`: пн–пт + исключения администратора; праздники 2026 года внесены миграцией и требуют сверки). Норма отдела, если не задана, — сумма норм его инженеров (`normComputed`).
6. **Права:** инженер — только себя, руководитель — свой отдел (и задаёт нормы своему отделу), администратор — всех, копирует нормы прошлого месяца, правит календарь и запускает пересборку. Отдел пользователя берётся из его карточки инженера в `directory-service`.
7. **Пороги цветов** (70 % и 90 %) задаются переменными `DASHBOARD_RED`, `DASHBOARD_YELLOW`.
