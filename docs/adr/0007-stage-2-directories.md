# ADR 0007. Справочники: устройство кода и данных (этап 2)

- Статус: принято
- Дата: 2026-10-23

## Решения

1. **Новые общие модули без бизнес-логики.**
   - `common-core` (без Spring): исключения `NotFoundException` (404), `ConflictException` (409) и `BusinessRuleException` (422), постраничные `PageQuery`/`PageResult`, генератор UUID v7, проверка ИНН/КПП/ОГРН с контрольными суммами.
   - `common-persistence`: базовая JPA-сущность с версией, аудитом и мягким удалением, белый список сортировок, сборщик условий JPQL.
   - `common-import`: чтение Excel (.xlsx) и CSV (разделитель «;» или «,», кодировка UTF-8 или Windows-1251), шаблоны импорта.
2. **Слои сервиса.** Домен — неизменяемые `record` с проверками в конструкторе. Прикладные сервисы — это и есть сценарии (use cases); отдельные интерфейсы `port.in` не заводятся, пока у сценария одна реализация. Команды прикладного слоя (`*Command`) служат телом запроса и несут аннотации Bean Validation; доменные проверки дублируют главные правила, чтобы домен был защищён и без веб-слоя.
3. **Права.** Проверяются в прикладном слое через `@PreAuthorize` (включено `@EnableMethodSecurity` в `common-web`): добавлять — все; изменять и удалять — `DEPARTMENT_HEAD`, `ADMIN`; инженеры и отделы сервисной компании, а также импорт — только по правилам раздела 11 `SPEC.md`.
4. **Оптимистичная блокировка.** Версия передаётся в теле запроса (`version`), а не заголовком `If-Match`: так проще генерируемому клиенту. Несовпадение — 409 с понятным текстом. Дополнительно работает `@Version` JPA.
5. **Идемпотентное создание.** Тело создания может содержать `id`, выданный клиентом (UUID v7); повтор запроса возвращает уже созданную запись. Это задел для офлайн-режима (раздел 17).
6. **Мягкое удаление** справочников (`deleted_at`). Удаление используемой записи запрещено (409): организацию с техникой или подразделениями, подразделение с вложенными или техникой, тип с техникой, отдел с инженерами.
7. **Номера** техники и запчастей хранятся нормализованными (верхний регистр, без пробелов по краям; в госномере пробелы удаляются). Поиск по части номера — `lower(...) LIKE` с триграммными индексами `pg_trgm`.
8. **Инженеры и Keycloak.** Карточка инженера и учётная запись создаются вместе: `directory-service` вызывает Keycloak Admin API под служебным клиентом `acts-directory` (client credentials). Если сохранить карточку не удалось, учётная запись удаляется. `GET /api/v1/engineers/me` находит карточку по `sub` токена, а при первом входе — по логину и запоминает связь.
9. **Демо-данные** лежат в `db/demo/R__demo_data.sql` и подключаются только переменной `FLYWAY_LOCATIONS` (так сделано в `docker-compose.yml`); в продакшен они не попадают.
10. **Генерация Java из OpenAPI отложена.** Контракты в `contracts/openapi/` остаются источником правды для фронтенда (Orval), Java-контроллеры пишутся по ним вручную. Генератор интерфейсов для Spring Boot 4 и Jackson 3 пока не проверен; вернёмся к этому, когда появится надёжная версия (бэклог).

## Последствия

- Новый справочник добавляется по тому же образцу: `record` в домене, порт, сервис с `@PreAuthorize`, JPA-сущность от `AuditedJpaEntity`, адаптер, контроллер, миграция, раздел контракта.
- События `OrganizationUpdated` и `EquipmentUpdated` пока не публикуются: публикатор outbox появится на этапе 3, и тогда сервисы начнут писать в `outbox` в той же транзакции.
