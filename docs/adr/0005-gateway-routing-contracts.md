# ADR 0005. Маршрутизация по ресурсу и контракты API

- Статус: принято
- Дата: 2026-10-23

## Решение

- Шлюз направляет запросы по ресурсу: `/api/v1/acts/**` → `act-service`, `/api/v1/organizations/**` → `directory-service` и т. д. Полный список — в `services/api-gateway/src/main/resources/application.yml`. Новый ресурс — новая строка, существующие маршруты не меняются.
- Служебный эндпоинт каждого сервиса `/api/v1/system/info` доступен через шлюз как `/api/v1/system/{service}/info`; на нём построен экран «Состояние системы».
- Contract-first: OpenAPI-файлы в `contracts/openapi/` — источник правды. Фронтенд генерирует клиент Orval (`npm run api:generate`); CI падает, если сгенерированный клиент не совпадает с контрактом.
- Генерация Java-интерфейсов контроллеров из контрактов (`openapi-generator-maven-plugin`, режим `interfaceOnly`) подключается на этапе 2, когда появятся первые бизнес-эндпоинты. На этапе 1 единственный эндпоинт общий для всех сервисов и живёт в `common-web`.
- Фронтенд работает через Nginx, который проксирует `/api/` на шлюз: браузер видит один адрес, CORS не нужен. В режиме разработки то же делает прокси Vite.
