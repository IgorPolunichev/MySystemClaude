# ADR 0015. Письма по актам (этап 8)

- Статус: принято
- Дата: 2026-10-25

## Решения

1. **Порты** (раздел 10 SPEC.md): `ContactDirectory` (адресная книга), `TemplateStore` + `TemplateRenderer` (шаблоны FreeMarker), `MailTransport` (SMTP и `.eml`) — их можно вынести в будущий сервис уведомлений.
2. **Вложения формируются при нажатии «Отправить»**, с правами пользователя (Excel каждого акта из `document-service`), и хранятся вместе с письмом (`email_attachment`, до 20 МБ; больше — только архивом ZIP). Поэтому фоновая отправка с повторами не нуждается в токене пользователя. Вариант «ссылки на скачивание вместо вложений» — в бэклоге.
3. **SMTP:** письмо ставится в очередь (`QUEUED`), фоновая задача каждые 10 с отправляет его от общего ящика (`MAIL_FROM`) с адресом пользователя в `Reply-To`. Ошибка — повтор через 1, 5, 15, 60 минут; после 5 попыток `FAILED` с текстом ошибки в журнале. Строки очереди блокируются `FOR UPDATE SKIP LOCKED`.
4. **`.eml`:** то же письмо с заголовком `X-Unsent: 1` — Outlook открывает его как черновик для отправки из своего ящика. Такое письмо тоже считается отправленным (событие `EmailSent`, режим `EML`).
5. **Отметка «Отправлен»:** `mail-service` пишет `EmailSent` в свой outbox (отправка в RabbitMQ — как в ADR 0014), `act-service` слушает очередь `acts.mail-events` и обновляет `work_act.last_sent_at` и `sent_count` (событие применяется один раз). Повторная отправка разрешена, предпросмотр предупреждает о ней и о незакрытых актах.
6. **FreeMarker** без доступа к Java-классам из шаблона; в HTML-теле значения экранируются. Шаблон с ошибкой не сохраняется — проверяется на тестовом акте. Переменные: `acts` (номер, организация, период, техника, краткое описание, часы), `sender` (ФИО, почта; должность и телефон — пока пустые), `today`, `totalHours`.
7. **Адресная книга:** контакт уникален по адресу; привязка к организации-заказчику с отметкой «по умолчанию» подставляет получателей в предпросмотр; группы; импорт CSV или Excel (существующие адреса обновляются) и экспорт CSV для Excel.
8. В Docker Compose письма уходят в **Mailpit** (http://localhost:8025) — ни одно письмо не попадёт наружу, пока не задан настоящий SMTP (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_AUTH`, `SMTP_STARTTLS`, `MAIL_FROM`).

## Экраны (этап 8б)

- Реестр: акты выбираются галочками (черновики и аннулированные — нельзя), кнопка «Сформировать письмо»; у отправленных актов отметка «отправлен».
- Карточка акта: «Отправить письмом», отметка «отправлен ДД.ММ.ГГГГ», «Письма по акту» (журнал по этому акту).
- Мастер письма: шаблон, «Кому» (подставлены получатели заказчика) и «Копия / Скрытая копия» с подсказками из адресной книги, выбор группы добавляет всех её участников, можно ввести новый адрес; тема и простой редактор текста (жирный, списки; таблица актов — из шаблона); вложения и «одним архивом ZIP»; «Отправить» и «Скачать .eml».
- Раздел «Почта»: журнал отправок (статус, попытки, текст ошибки, повторное скачивание .eml), адресная книга (контакты, получатели по умолчанию для заказчика, группы, импорт и экспорт), шаблоны (администратор; HTML и FreeMarker со списком переменных).
- Предложение сохранить новый адрес в адресную книгу после отправки — в бэклоге.
